# AIL LABS — Production Setup & Security Notes

## Production architecture
- Public site: Cloudflare Worker/static assets.
- Admin panel: /admin/
- API: /api/*
- Admin authentication: runtime environment secrets.
- Session: signed HttpOnly ail_session cookie.
- Database: PostgreSQL/Neon.
- Procurement AI: protected by admin authentication and a server-side OpenAI API secret.

## Admin authentication
Production admin login uses:
- ADMIN_USERNAME
- ADMIN_PASSWORD
- SESSION_SECRET

Never commit the values of these variables to GitHub, documentation, screenshots, chat, or client-side JavaScript.

Login flow:
1. Open /admin/.
2. Submit the runtime admin username/password.
3. POST /api/auth/login validates the credentials.
4. A signed, HttpOnly session cookie is created.
5. Protected admin endpoints require req.session.isAdmin.

There is no database password-reset flow. To rotate the admin password, update the Cloudflare runtime secret ADMIN_PASSWORD and redeploy/restart the Worker.

## Security rules
- Do not store database URLs, API keys, admin passwords, or session secrets in source control.
- Rotate any credential that has previously been committed or exposed.
- Keep OPENAI_API_KEY server-side only.
- Keep Procurement AI behind admin authentication.
- Do not expose secrets through health checks, logs, or API responses.
- Use Cloudflare or CI/CD secret storage for production runtime secrets.

## Production validation checklist
- [ ] ADMIN_USERNAME configured in Cloudflare.
- [ ] ADMIN_PASSWORD configured in Cloudflare.
- [ ] SESSION_SECRET configured in Cloudflare.
- [ ] OPENAI_API_KEY configured in Cloudflare.
- [ ] No real secret values exist in tracked files.
- [ ] Admin login succeeds.
- [ ] Admin logout succeeds.
- [ ] Unauthenticated admin API requests return 401.
- [ ] Procurement AI remains inaccessible without admin session.
- [ ] Public catalog and checkout remain functional.

## Credential exposure warning
If a credential was ever committed to the repository, treat it as compromised even after the file is edited. Rotate the credential in the real provider first, then remove the exposed value from the repository.
